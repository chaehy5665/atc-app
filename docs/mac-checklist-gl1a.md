# Mac checklist (ATC-247, GL1a: the GitHub PR list and the Work window)

Run after the PR is merged and `Tools/build-app.sh` builds, with `docs/mac-checklist-gl.md` done (the GitHub OAuth App is registered, its client ID is in Settings, and you can sign in). The app target (the token refresh, the transport, the Work window, the popover line, Settings) was written on Linux and **has not been built or run on a Mac**. Report in words, no screenshots, and never paste a token or a device code anywhere. Use scratch repositories or your own; nothing here is committed.

1. `Tools/build-app.sh` succeeds. Paste compiler errors if not.
2. **Settings > GitHub PR 목록**: type `bad` and Apply: a red message names it and nothing is saved. Type one real `owner/name` per line and Apply: the text is kept after reopening Settings. The cap field shows 1000; set 50 and Apply: it shows 100 (the lowest allowed); set 9999: it shows 4000; set it back to 1000.
3. Signed out of GitHub: the popover has **no** GitHub line, and Window > Work (⌘⇧W) opens a window that says to sign in. Signed in with no repository listed: the popover line says to add one in Settings.
4. Signed in with a repository: open the popover. Within a few seconds a line `GitHub: N open` (plus `· M CI failing` and `· K review requested` only when they are above zero) appears under the status line. The numbers match the repository's open PR list on github.com (draft PRs count as open). Clicking the line closes the popover and opens the Work window.
5. **Work window**: one list, a row per open PR with its title, `repo #number · author · age`, the CI word (`CI failing`, `CI pending`, `CI passing`, `CI —`) and `review requested` when you are asked. `All` and `Review requested` switch the filter; **Refresh** reloads. The window can be resized and remembers its frame. Titles that contain `<b>`, a link or markdown show as plain text.
6. A **row click** (not on the button) opens the PR in the default browser, never in the atc window, even with the Settings choice "앱 창". **Decide in atc ↗** opens the atc window on STRIPS (or the browser, with ⌥ held or the choice "브라우저"). There is no other button or action in the window: nothing merges, comments or re-runs anything.
7. Closing the Work window with the atc window closed: the Dock icon goes away. With the atc window open, closing Work keeps it, and closing the atc window while Work is open keeps the Dock icon until Work closes.
8. **Polling only while open.** With the popover and the Work window both closed, `nettop -m tcp -p Annunciator` (or Little Snitch, if you run it) shows no connection to `api.github.com`. Open the popover: a request goes out at once and then about every 60 s; close it: they stop. Opening the Work window while the popover is open does not double the rate.
9. **Cost of an open window** (record the numbers in the PR). Run `gh api rate_limit --jq .resources.core` before and after leaving the Work window open for 30 minutes on a quiet repository, with atc stopped if you can. Write: requests used in 30 minutes, requests per hour, and the number the app shows in Settings (`이번 시간 사용`). Do the same for a repository with a PR whose check is running.
10. **`304` is free.** With the window open on an unchanged repository: `gh api rate_limit --jq .resources.core.remaining` before, wait for two polls (2 minutes), after. `remaining` should barely move (it does move if atc is spending in the background, so note that). If it drops by one per poll, the docs claim is wrong for this token type: report it and `RateBudget.record(notModified:)` must count a `304`.
11. **Updated PR.** Push a commit to a PR (or update its title). Within 60 s of the next poll the row's age resets and the CI word follows the new checks. A check that finishes without a push changes `CI pending` to `CI passing` or `CI failing` within about a minute.
12. **Token refresh.** The user token lives 8 hours. After more than 8 hours since sign-in (leave the app running, window open now and then), the list keeps working without a new sign-in. In Keychain Access the `dev.atc.annunciator.github` items `access`, `refresh` and `expiry` exist; the `expiry` text is a time about 8 hours after the last refresh. If you cannot wait, edit nothing: report what you saw after the next workday.
13. **Expired or revoked.** Revoke the OAuth App's authorization on github.com (Authorized OAuth Apps) (Settings links to it from the GitHub section), then wait for a poll: the popover line becomes `GitHub: 다시 로그인이 필요합니다` and no further requests go out (check as in step 8). Sign out and sign in again: the list returns without restarting the app.
14. **Rate limit.** Set the cap to 100 and open the window on a few repositories, or use `gh api` in a loop to spend the user's budget. When the cap is reached the popover says `GitHub: 시간당 요청 한도에 도달, HH:MM에 다시 시작` and the Work window header says the same; at that time polling resumes by itself. When GitHub itself answers 403/429, the line is `GitHub rate limited, retrying at HH:MM`. Neither lights the MASTER light or changes the menu bar title.
15. **No leaks.** Console.app filtered on `Annunciator` while doing steps 4, 12 and 13: no token, no `Authorization`, no URL with a query appears (the app logs nothing). `defaults read dev.atc.annunciator` shows the repository list, the cap and the client IDs only.
16. Sign out of GitHub: the popover line disappears, the Work window says to sign in, the Keychain items (including `expiry`) are gone, and no request goes out.
