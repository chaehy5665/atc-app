# Mac checklist (ATC-248, GL1b: the Linear issue list)

Run after the PR is merged and `Tools/build-app.sh` builds, with `docs/mac-checklist-gl.md` done (the Linear OAuth application is registered, its client ID is in Settings, and you can sign in to Linear) and `docs/mac-checklist-gl1a.md` done. The app target (the Linear token refresh, the Work window switch, the popover line, Settings) was written on Linux and **has not been built or run on a Mac**. Report in words, no screenshots, and never paste a token anywhere. Nothing here is committed; do not write team or workspace names into the repository or the PR.

1. `Tools/build-app.sh` succeeds. Paste compiler errors if not.
2. **Settings > Linear 이슈 목록**: a field for team keys. Type `bad key` and Apply: a red message names the entry and nothing is saved. Type `1AB` the same. Type your team key (lowercase is fine, it is upper-cased) and Apply: the field shows it again after reopening Settings.
3. Signed out of Linear: the popover has **no** Linear line, and the Work window's **Linear** list says to sign in. Signed in with no team key: the popover line says to add one in Settings.
4. Signed in with a team key: open the popover. Within a few seconds a line `Linear: N Todo · M Started` appears under the GitHub line (or inside the folded `DUTY · GitHub 3 · Linear 6 · …` summary). The numbers match the team's Todo and In Progress/Started issues in Linear (Backlog, Triage, Done and Canceled are not counted). Report any difference, and whether a custom state (for example `In Review`) of type Started is counted.
5. Click the Linear line: the popover closes and the Work window opens on the **Linear** list. Click the GitHub line: it opens on **GitHub PR**. The switch at the top moves between them; the `All` / `Review requested` filter is only there for GitHub.
6. The Linear list shows one row per issue: title, `KEY · age`, and Linear's own state name. A row click opens the issue at `https://linear.app/…` in the default browser. **Decide in atc ↗** opens the atc window at the FLIGHT drawer of that key (`#flight/<KEY>`). Report if the drawer does not open.
7. More than 250 issues (only if the team has that many): the line ends with `+` and the window header says the first 250 only.
8. **Request cost.** With the window open and nothing changing, count Linear requests for ten minutes (Console is not needed: use Linear's API settings if it shows request counts, otherwise note the `X-RateLimit-Requests-Remaining` change you can see from one `curl` with your own token, never pasted anywhere). Expect one to five requests a minute, not more. Report the number.
9. **Rate-limit headers.** In one `curl` of the GraphQL endpoint with your own token, note the names of the rate-limit headers in the response (`X-RateLimit-Requests-*`, `Retry-After`?) and whether the reset is in seconds or milliseconds. Report them in words: the app reads these names and assumes seconds.
10. **Expired token.** Linear access tokens last 24 hours. Leave the app signed in over a day (or sign out of Linear's side by revoking the application in Linear's settings, then wait for a poll): the popover line becomes `Linear: 다시 로그인이 필요합니다` and no further Linear requests go out. After a normal 24-hour expiry with the refresh token intact there is no message at all: the list keeps working. Sign out and in again: the list returns without restarting the app.
11. **Rate limit** (optional, only if you can reach it): the line says `Linear rate limited, retrying at HH:MM` and polling resumes by itself. It never lights the MASTER light or changes the menu bar title.
12. Change the team key in Settings while the window is open: the old rows disappear and the new team's rows load within a few seconds.
13. Sign out of Linear: the popover line disappears, the Linear list says to sign in, the Keychain items for Linear are gone, and no request goes out. GitHub keeps working.
14. Console.app, filter on `Annunciator`, during steps 4 to 6: no token, no issue title and no team key appear (the app logs nothing in this path).
